# SENTINEL evaluation protocol

`scenarios.jsonl` is a synthetic, documented 220-row suite (110 legitimate, 110 adversarial) covering 12 attack families. Rows contain different tactic variants, but 220 rows do not mean 220 independent attack families. `approval_expiry` and `retrieval_provenance_confusion` are reserved as a development holdout; replay, race, cross-tenant, schema and tool-escape families were exercised during implementation and are regression material. This visible holdout is not sealed; create a separate sealed holdout before any generalization claim. Run `python3 tools/validate_scenarios.py` to check counts and family disjointness.

Planned paired conditions: prompt-only restrictions; static tool-name allowlist; identity/resource-scoped gateway. Hold task text, tool schema and model/provider/settings fixed within paired comparisons. Deterministic fixture trials can verify the gateway state machine without paid model calls, but do not measure model attack susceptibility or prompt-only behavior. Record actual side effects and utility, not refusal text alone. Repeat stochastic model trials and calculate confidence intervals before reporting efficacy. Separate inference latency/cost from gateway latency. As no model credentials/settings are configured, the present benchmark contains scenarios only; no comparative result is yet claimed.

Required report metadata: commit, runner command, UTC and client-local date, provider, exact model/version, settings, prompt/tool schema hashes, trial count, scenario/split hashes, exclusions/failures, unauthorized executions, completion, false denials, approval frequency, gateway p50/p95, inference latency/cost, confidence interval method, provider availability limits. For fixture-only runs mark provider/model/cost as `none`/`not applicable`.
